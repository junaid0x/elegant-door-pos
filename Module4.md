## API Endpoints

| Method | Endpoint | Access | Description |
|--------|----------|--------|-------------|
| GET | `/api/categories` | Protected | Get all categories (sorted by newest first) |
| GET | `/api/categories/:id` | Protected | Get a single category by ID |
| POST | `/api/categories` | Protected | Create a new category |
| PUT | `/api/categories/:id` | Protected | Update an existing category |
| DELETE | `/api/categories/:id` | Protected | Delete a category (blocks if products use it) |

## MongoDB Schema Explanation

### Category Schema (`server/models/Category.js`)

```
Category {
  name:        String   — Required, unique, trimmed, max 50 chars
  description: String   — Optional, trimmed, max 200 chars, defaults to ''
  createdAt:   Date     — Auto-generated by Mongoose timestamps
  updatedAt:   Date     — Auto-generated by Mongoose timestamps
}
```

**Key design decisions:**
- `name` is **unique** — prevents duplicate categories at the database level
- `name` is **trimmed** — removes leading/trailing whitespace automatically
- `description` defaults to empty string `''` — avoids null values in the UI
- `timestamps: true` — Mongoose auto-manages `createdAt` and `updatedAt`
- Follows the same pattern as `User.js` and `Product.js` in the project

**How it connects to Product:**
The existing `Product.js` model has a `category` field:
```javascript
category: {
  type: mongoose.Schema.Types.ObjectId,
  ref: 'Category',
  required: true,
}
```
This creates a relationship: each Product references one Category by its `_id`.

## CRUD Flow Explanation

### Create Flow
```
1. User clicks "New Category" button
2. CategoryModal opens (empty form)
3. User fills in name (required) + description (optional)
4. Client-side validation runs (name required, max lengths)
5. POST /api/categories with { name, description }
6. Backend validates: name required, checks for duplicates (case-insensitive)
7. Category.create() saves to MongoDB
8. Response: { success: true, data: category }
9. Toast: "Category created successfully"
10. Table auto-refreshes via fetchCategories()
```

### Read Flow
```
1. Categories page mounts
2. useEffect triggers fetchCategories()
3. GET /api/categories
4. Backend: Category.find().sort({ createdAt: -1 }).lean()
5. Response: { success: true, count: N, data: [...] }
6. Categories rendered in table
```

### Update Flow
```
1. User clicks pencil icon on a row
2. CategoryModal opens (prefilled with existing data)
3. User modifies fields
4. PUT /api/categories/:id with { name, description }
5. Backend validates: category exists, name not duplicate (excludes self)
6. category.save() updates MongoDB
7. Toast: "Category updated successfully"
8. Table auto-refreshes
```

### Delete Flow
```
1. User clicks trash icon on a row
2. DeleteDialog opens: "Are you sure you want to delete 'X'?"
3. User clicks "Delete"
4. DELETE /api/categories/:id
5. Backend checks: any products using this category?
   ├─ Yes → 400: "Cannot delete — N product(s) are using this category"
   └─ No  → Category.findByIdAndDelete() removes from MongoDB
6. Toast: success or error message
7. Table auto-refreshes (on success)
```

## Frontend/Backend Connection

```
Categories.jsx (page)
  ├─ imports categoryService.js (API calls)
  │     └─ imports api.js (shared Axios instance)
  │           ├─ Base URL: /api (proxied by Vite → localhost:5001)
  │           ├─ Request interceptor: attaches JWT from localStorage
  │           └─ Response interceptor: handles 401 → redirect to /login
  │
  ├─ imports CategoryModal.jsx (create/edit form)
  │
  └─ Renders inside MainLayout (Sidebar + Header + content area)
        via ProtectedRoute in App.jsx
```

**Data flow for a create operation:**
```
CategoryModal → handleSubmit() → createCategory(formData)
  → api.post('/categories', data)
  → Vite proxy → http://localhost:5001/api/categories
  → protect middleware (verifies JWT)
  → createCategory controller
  → Category.create() → MongoDB
  → Response ← JSON { success, data }
  ← categoryService returns response.data
  ← handleSubmit shows toast, calls fetchCategories()
  ← Table re-renders with new data
```

## Modal Workflow Explanation

### CategoryModal Component (`client/src/components/CategoryModal.jsx`)

**Props:**
| Prop | Type | Description |
|------|------|-------------|
| `isOpen` | boolean | Controls modal visibility |
| `onClose` | function | Called when modal should close |
| `onSubmit` | function | Called with `{ name, description }` on form submit |
| `category` | object/null | If provided, modal opens in edit mode with prefilled data |
| `loading` | boolean | Disables buttons and shows spinner during API call |

**Behavior:**
1. **Create mode** — `category` is `null` → form starts empty, button says "Save Category"
2. **Edit mode** — `category` is provided → form prefilled, button says "Update Category"
3. **Auto-focus** — Name input auto-focuses when modal opens
4. **Escape key** — Pressing Escape closes the modal
5. **Backdrop click** — Clicking outside the modal closes it
6. **Validation** — Name required (max 50 chars), description optional (max 200 chars)
7. **Character counter** — Description field shows live character count (e.g., "45/200")
8. **Loading state** — Save button shows spinner, both buttons disabled during API call

### DeleteDialog Component (inline in Categories.jsx)

**Behavior:**
1. Shows category name in confirmation message
2. Two buttons: Cancel (white) and Delete (red)
3. Delete button shows spinner during API call
4. Both buttons disabled while deleting
5. Backdrop click or Cancel closes the dialog

## Common Issues / Fixes

### "Category name is required" even though name is filled
**Cause:** Whitespace-only names are rejected. The backend trims and checks `!name.trim()`.
**Fix:** Enter at least one non-whitespace character.

### "A category with this name already exists"
**Cause:** Duplicate check is case-insensitive. "Interior Doors" and "interior doors" are the same.
**Fix:** Use a different name, or edit the existing category.

### "Cannot delete — N product(s) are using this category"
**Cause:** Products reference categories by `_id`. Deleting would orphan products.
**Fix:** Reassign products to a different category first, then delete.

### Modal doesn't open
**Check:**
1. Is JavaScript console showing errors?
2. Is the `isOpen` state being set correctly?
3. Try refreshing the page.

### Categories not loading (blank table)
**Check:**
1. Is the backend running on port 5001?
2. Is the Vite proxy configured correctly in `vite.config.js`?
3. Check browser console for 401 errors (token expired — re-login).

### Dashboard doesn't show category count
**Note:** The dashboard controller was updated to directly require the Category model. Category count now updates automatically as you add/remove categories.
