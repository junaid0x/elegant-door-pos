# Module 20 – Prisma Foundation & MySQL Infrastructure Setup

## Overview
This module transitions the application architecture from a purely MongoDB-driven backend to a hybrid state by establishing the foundational infrastructure for Prisma and MySQL. As requested, no existing controllers, business logic, or frontend components have been migrated or modified during this phase.

## 1. Packages Installed
- `prisma` (devDependencies, v7.8.0) - The Prisma CLI.
- `@prisma/client` (dependencies, v7.8.0) - The auto-generated query builder.

## 2. Files Created
- `server/prisma/schema.prisma` - The definitive Prisma schema definition for MySQL.
- `server/prisma.config.ts` - Prisma v7 configuration file.
- `server/config/prisma.js` - A singleton instance of the Prisma Client to prevent connection exhaustion during development hot-reloading.
- `server/routes/healthRoutes.js` - A new Express router to expose database health checks.

## 3. Schema Implemented
The schema from `Prisma-Schema-Review.md` was perfectly implemented inside `prisma/schema.prisma`.
Key tables include:
- `users`
- `categories`
- `products`
- `product_variants` (Replaced the flat sizes array)
- `product_bundles` (Many-to-many junction table)
- `orders` & `order_items`
- `quotations` & `quotation_items`

## 4. Environment Variables Required
The `server/.env` file has been updated to require a `DATABASE_URL` variable.
Current value: `DATABASE_URL="mysql://root:@localhost:3306/elegant_doors_mysql"`

*Note: This must be updated to match the actual local MySQL server credentials before migrations can be run.*

## 7. Issues Encountered
1. **Prisma v7 Syntax Update:** Prisma v7 no longer supports the `url` property directly inside the `datasource db` block in `schema.prisma`. This was resolved by migrating the URL configuration into the new `prisma.config.ts` file generated by `npx prisma init`.
2. **Missing Local Database Server:** The local environment does not have a running instance of MySQL available on the default port. Therefore, the actual database tables have not been generated yet.

## 8. Next Recommended Step
**Action Required:** 
1. Start your local MySQL server (or provide a remote MySQL connection string in `server/.env`).
2. Run the command `npx prisma migrate dev --name init` inside the `server/` directory to generate the tables and the Prisma Client.
3. Start the backend server (`npm run dev`) and test the new health endpoint (`GET /api/health/db`).
